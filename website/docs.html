01 // Current Command Processing Flow

The current implementation does not use a three-lane command router. The executor handles pending security confirmations and greeting requests directly, routes explicit GitHub requests to the built-in GitHub plugin, and sends other non-empty requests to the Agent Brain. The Agent Brain asks LiteLLM for Python code using the configured model identifier Google Gemini / Groq Cloud / Multi-Provider Auto-Failover, then runs returned code in a Python subprocess.

Microphone/audio path (when voice mode is used) -> speech recognition and command transcription -> command executor -> pending security confirmation? handle confirmation/cancellation -> short greeting? return greeting -> explicit GitHub request? GitHub plugin -> GitHub REST API or local Git -> confirmation required for pushes and GitHub writes -> otherwise send request to Agent Brain -> LiteLLM completion (Google Gemini / Groq Cloud / Multi-Provider Auto-Failover) -> generated Python code -> Python subprocess (30-second timeout) -> result returned to UI

The model identifier includes cloud; do not assume requests are processed offline or that prompt text remains on the device. Generated code is executed with the application's user permissions. The website command simulator is illustrative and does not submit commands to the running application.

Universal AI Brain & Multi-Provider Core

PRIVACY68 supports any AI API key and any local offline model:
• Free Cloud APIs: Google Gemini 3.5 Flash, Groq Cloud LPU (GPT-OSS 120B / Qwen 27B), OpenRouter (100+ free models) with automatic failover.
• Local Offline Models: Connects to local or remote Ollama (http://127.0.0.1:11434), LM Studio (http://localhost:1234/v1), or any OpenAI-compatible server.
• Intra-Provider Cascading: Automatically shifts to sibling models if a provider deprecates an API identifier, healing settings in real time.

02 // Speech Pipeline & Acoustic Normalization

PRIVACY68 enforces a strict 100% Click-to-Speak hardware isolation architecture. The microphone is never open in the background, preventing eavesdropping and idle resource drain. When triggered, the 16kHz audio stream is captured, normalized, and transcribed:

  • Hardware Isolation: The microphone stream is opened strictly when the user activates Click-to-Speak (in the HUD or via hotkey), and closed immediately upon release.
  • Dynamic Peak Normalization: Every audio buffer is dynamically scaled using peak amplitude scaling:
    norm = (audio / peak) × 0.9
    This maximizes dynamic range, ensuring crystal-clear transcription for quiet speech without clipping or distortion.
  • Speech Autocorrection: Transcribed commands pass through autocorrect_speech_command() to strip vocal tics ("um", "uh"), repeated stutters ("open open"), trailing conjunctions, and common app typos.
  • Google Web Speech ASR: Instant cloud speech recognition with zero API keys or complex setups, achieving sub-100ms transcription latency.
  • Offline Faster-Whisper Fallback: For air-gapped environments, the system seamlessly falls back to local Faster-Whisper running on CUDA 12 or CPU (int8).

03 // Microphone Setup & Audio Diagnostics

Proper microphone levels ensure 100% accurate speech recognition. Follow these diagnostic steps:

1. Windows Privacy Permissions

Ensure Windows allows desktop apps access to the microphone: Navigate to Settings → Privacy & Security → Microphone. Toggle "Allow desktop apps to access your microphone" to ON.

2. Audio Level Benchmark

Test your microphone's live input sensitivity and background noise floor by running this test command in PowerShell:

python -c "import sounddevice as sd, numpy as np; d=sd.rec(int(16000*3), 16000, 1, 'float32'); sd.wait(); print('Peak:', round(float(np.max(np.abs(d))), 4), 'RMS:', round(float(np.sqrt(np.mean(d**2))), 4))"
ACOUSTIC STATE ACCEPTABLE RMS ACCEPTABLE PEAK RECOMMENDED ACTION
Room Silence < 0.005 < 0.015 Optimal noise floor. Audio stream remains completely silent until Click-to-Speak is engaged.
Normal Speech > 0.020 > 0.080 Ideal speech level. Transcribed with 99%+ accuracy after (audio / peak) × 0.9 normalization.
Low Sensitivity < 0.010 < 0.030 Increase microphone volume to 85% in Windows Sound Control Panel.

04 // 3-Tier Security Guard & Confirmation Policy

PRIVACY68 protects system integrity using a real-time 3-Tier Security Execution Model. Any operation generated by the Agent Brain or requested via voice or text is evaluated before execution, ensuring destructive or critical system actions are gated behind explicit user confirmation.

Security Execution Tiers

LEVEL RISK CLASSIFICATION EXAMPLE ACTIONS EXECUTION POLICY
Tier 1 SAFE (Instant) Launch apps, media controls, web searches, window minimize/focus, screenshots, read-only queries Executed immediately without interruption.
Tier 2 SENSITIVE (Audited) File creation/modification, closing applications, clipboard updates, network state checks Executed with visual feedback and logged in audit history.
Tier 3 CRITICAL (Confirmation Gated) File/folder deletion, Git push, terminating processes, disk formatting, registry/system edits Halted. Prompts user with 15-second timeout window. Requires explicit "yes" or "proceed" to run.

Interactive Safety Loop

When a Tier 3 action is flagged, the HUD displays a confirmation prompt. If the user replies "cancel", "no", or if the 15-second confirmation window expires, the pending action is discarded safely with zero impact on the host operating system.

NVIDIA GPU (CUDA 12) float16 (Tensor Cores) ~120ms – 160ms ~1.4 GB VRAM

Zero-Config CUDA Runtime Manager

PRIVACY68 operates with zero-setup cloud APIs (100% Free Google Web Speech Recognition), removing all requirements for 800MB local CUDA DLLs. Note that official NVIDIA CUDA Toolkit installers (such as CUDA 13.x) have mismatched DLL versions and omit cuDNN entirely.

PRIVACY68 eliminates this manual setup: the built-in CUDA Manager allows one-click runtime installation. Simply click "Download CUDA (~450MB)" in the Control Center Hardware card to automatically download and register the pre-compiled cuBLAS 12 and cuDNN 9 DLLs into %APPDATA%\PRIVACY68\cuda\bin\.

06 // Plugin Architecture & Mobile Web Remote

The desktop dashboard includes a plugin registry for viewing registered integrations, changing enabled state, creating a template, installing a Python plugin file, and uninstalling user plugins. It also supports connecting a GitHub personal access token through Windows Credential Manager. External Python plugins are loaded from %APPDATA%/PRIVACY68/plugins/; plugin code runs with the current user's permissions.

Explicit GitHub requests are routed directly to the built-in GitHub integration for current-repository status/push, repository and issue/pull-request listings, and issue/pull-request creation. Pushes and create actions require confirmation. Other plugin registrations are not automatically dispatched. The plugin registry is not a sandbox or an execution boundary.

See the built-in plugins and extension details.

Mobile Web Remote (Local Wi-Fi)

Control your computer from your smartphone or tablet over the local network. The remote server does not provide authentication; only enable it on a trusted network and keep in mind commands run on the host computer.
